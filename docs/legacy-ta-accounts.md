# บัญชีผู้ช่วยสอนเดิม และการส่งข้อมูลวันประชุม

ชุดนี้สร้างเฉพาะบัญชีบทบาท `ta` พร้อมรหัสนักศึกษาและระดับการศึกษา ไม่สร้างคำขอ TA ไม่อนุมัติเอกสาร ไม่เปลี่ยนบัญชีเดิม และไม่ส่งอีเมลขณะนำเข้า

ผลการรันวันที่ 11 พฤศจิกายน 2569 ในฐานข้อมูล `localhost:5432/ta_payment`: สร้างบัญชีใหม่ 129 คน เก็บข้อมูลพร้อมส่ง 129 คน และยังไม่ได้ส่งอีเมล ข้าม 8 คนที่อีเมลตรงกับบัญชีเดิมแต่รหัสนักศึกษาต่างกัน อีก 20 คนจากรายชื่อเดิม 157 คนยังไม่ผ่านการเตรียมข้อมูล (19 คนไม่พบรหัสในไฟล์นักศึกษา และ 1 คนยังไม่ยืนยันระดับการศึกษา)

ตรวจหลังนำเข้าแล้ว: บัญชีรวมเพิ่มจาก 19 เป็น 148 บัญชี มีประวัติรหัสนักศึกษาสำหรับบัญชีใหม่ครบ 129 คน คำขอ TA คงเดิม 10 รายการ และไม่มีรายการอีเมล/การแจ้งเตือนสำหรับบัญชีใหม่ โหมดตรวจสอบการส่งพบพร้อมส่ง 129 คน และการตรวจนำเข้าซ้ำพบ 129 คนเป็นบัญชีเดิมโดยไม่สร้างซ้ำ

## การนำเข้า

ใช้ข้อมูลที่จับคู่รหัสนักศึกษาได้ ชื่อและอีเมลจากไฟล์นักศึกษา ระดับการศึกษาที่ระบุชัดเจนในเอกสารเก่า ไม่ใช้เบอร์โทรเก่าที่อาจเปลี่ยนไป ข้อมูลนำเข้าอยู่ใน `data/account-imports/legacy-ta-20261111-ready.json` ซึ่งไม่รวมใน Git

```bash
cd /Users/ohmmy/ta_payment/ta_payment_back

# ดูผลตรวจบัญชีซ้ำ ไม่เขียนฐานข้อมูล
go run ./cmd/ta-accounts -mode import \
  -input data/account-imports/legacy-ta-20261111-ready.json

# สร้างบัญชีและเก็บรหัสผ่านแบบเข้ารหัส ไม่ส่งอีเมล
go run ./cmd/ta-accounts -mode import \
  -input data/account-imports/legacy-ta-20261111-ready.json -apply
```

คำสั่งเลือกผู้ดูแลระบบที่เปิดใช้งานเพียงคนเดียวเป็นผู้ดำเนินการใน audit log หากมีหลายคน ให้เพิ่ม `-actor-email อีเมลเจ้าหน้าที่` ทุกโหมด ข้อมูลซ้ำหรือขัดกับบัญชีเดิมจะถูกข้ามโดยไม่เขียนทับ

บัญชีใหม่มีรหัสผ่านสุ่มเฉพาะคน บังคับเปลี่ยนรหัสผ่านครั้งแรก และยังไม่มีสถานะกรอกโปรไฟล์ครบ รหัสผ่านเก็บเฉพาะในไฟล์เข้ารหัส `data/account-imports/legacy-ta-20261111.enc` โดยใช้ `PII_ENC_KEY` จากการตั้งค่าระบบ ไฟล์นี้เป็นทั้งข้อมูลส่งและบันทึกสถานะการส่ง จึงต้องเก็บคู่กับคีย์อย่างปลอดภัย ไม่ใส่ Git และไม่เปิดเผยรหัสผ่านในรายงาน

หากไฟล์เข้ารหัสมีอยู่แล้ว การนำเข้ารอบเดิมจะหยุดเพื่อรักษารหัสผ่านเดิมไว้ ใช้โหมดดูผลเพื่อตรวจสอบ หรือโหมดส่งเพื่อดำเนินการต่อ ห้ามลบไฟล์นี้แล้วนำเข้าใหม่เพื่อกู้รหัสผ่าน

## วันประชุม

1. เปิดฐานข้อมูลและตรวจการตั้งค่า SMTP ของระบบ
2. ตั้ง `APP_BASE_URL` เป็น URL ที่นักศึกษาเปิดได้จริง เช่น URL ของระบบที่ใช้ในวันประชุม ปัจจุบันการตั้งค่าในเครื่องมี `localhost` เป็นค่าแรก จึงต้องเปลี่ยนหรือกำหนดผ่าน environment ก่อนส่ง ห้ามใช้ URL ตัวอย่างแทน URL จริง
3. ตรวจรายการก่อน แล้วจึงรันส่ง:

```bash
cd /Users/ohmmy/ta_payment/ta_payment_back

# ตรวจบัญชีและรหัสผ่านที่ยังพร้อมส่ง ไม่ส่งอีเมล
./scripts/send-legacy-ta-credentials.sh

# ส่งจริงเมื่อถึงวันประชุมเท่านั้น
./scripts/send-legacy-ta-credentials.sh -send
```

คำสั่งอ่าน `.env` ของ backend ใช้แม่แบบอีเมลข้อมูลเข้าสู่ระบบเดิมของระบบ ส่งแยกถึงอีเมลของแต่ละบัญชี พร้อมชื่อผู้ใช้ รหัสผ่านชั่วคราว ลิงก์เข้าสู่ระบบ และคู่มือ TA ไม่ได้ส่งแบบรวมรายชื่อผู้รับ

ตัวเลือก `-only รหัสนักศึกษา` จำกัดผู้รับคนเดียว และ `-limit 10` จำกัดจำนวนที่ส่งในรอบนั้น เมื่อส่งสำเร็จจะทำเครื่องหมาย `sent` และลบรหัสผ่านจากรายการในไฟล์เข้ารหัส การรันซ้ำจะข้ามผู้ที่ส่งสำเร็จแล้ว บัญชีที่เปลี่ยนอีเมล รหัสนักศึกษา หรือรหัสผ่านไปแล้วจะไม่ถูกส่งด้วยข้อมูลเก่า

หากโปรแกรมหยุดระหว่างส่ง หรือ SMTP ตอบกลับไม่ชัดเจน รายการจะอยู่สถานะ `sending` หรือ `needs_review` และจะไม่ส่งซ้ำอัตโนมัติ ต้องตรวจ mail log/audit log ก่อนจัดการรายนั้นต่อ ส่วนรายการ `pending` ที่เหลือยังรันต่อได้ คำสั่งใช้ไฟล์ `.lock` เพื่อกันการรันชุดเดียวกันพร้อมกัน หากมี lock ค้าง ต้องตรวจว่าไม่มีโปรแกรมเดิมกำลังทำงานก่อนลบ lock

โหมดส่งจะปฏิเสธการส่งเมื่อยังไม่มี SMTP หรือ URL เข้าสู่ระบบเป็น localhost คำสั่งเตรียมไว้แล้ว แต่ไม่มีการตั้งเวลาส่งอัตโนมัติ
